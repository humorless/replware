每個月花最多時間整理的那份 Excel，怎麼判斷它是不是資料工程問題？

陳家宏（Laurence Chen）｜睿博資訊創辦人｜最後更新 2026-10-23

先問兩個問題：這件事是不是已經有人用 Excel 做出第一版？它是不是每個月、每一季都要重做一次？ 兩個答案都是「是」，它多半是資料工程問題。計算規則已經寫在 Excel 裡，缺的是一條每期可以自動重跑的資料管線。

給財務與營運主管

常見的情況

月結前那幾天，總有一份 Excel 要花掉好幾個人的時間：

  • 從 ERP 和各系統匯出資料，用 vlookup 拼起來，每月重拼一次。
  • 幾個人接力完成一份檔案，每人負責幾個欄位。睿博出版的《從試算表到資料平台》稱這種分工為「試算表流水生產線」。
  • 主管問「這個數字怎麼來的？」，只有做表的人答得出來。
  • 業務部和財務部的營收數字對不起來，因為兩邊各自抽資料、套公式。

判準一：已經有 Excel 第一版

同一本書第十章的啟發法：凡是已經先被 Excel 做出第一版解決方案的問題，都很有可能是資料工程的問題。 有第一版，代表業務規則已經被定義、被驗證過，剩下的是讓它在資料庫裡自動執行。

書中的例子：一位客戶用 Excel 算先進先出法（FIFO）的存貨成本，工程師寫了 500 多行程式還沒完成；改在資料庫用 SQL 實作，約 50 行，每一步的中間結果都能像 Excel 一樣檢查。

判準二：每個週期都要重做

資料分析常是一次性的，報告交出去就結束。管理會計不一樣：預算改好幾輪，每輪依公司自訂的維度彙總，每季再和實際數字比一次（預實分析）。 同樣的比對做到第十二次，就該做成資料管線。

管理會計的特性在 Excel 裡做成資料管線之後
同一份數字有多個版本初版預算、修正後預算各一份檔案，靠人工逐格比對每個版本存在同一張表，差異清單自動產生
維度由公司自己定義每次彙總都要重新整理部門、產品的對照關係維度定義一次，所有報表共用
每個週期都要重做每月、每季從頭再拼一次新一期資料進來，管線重跑

為什麼常落在管理會計

財務會計對外，格式由會計準則規範，大部分工作 ERP 已經處理。管理會計對內，看哪些數字、怎麼切，每家公司都不同，ERP 管不到的部分多半留在 Excel 裡。 所以企業裡最大量的資料工程需求，常在財務部、業務部每月整理的 Excel 裡，不在資料分析專案裡。

睿博做的是資料工程這一段：把貴公司既有的計算邏輯搬進資料平台、每期自動重跑。會計判讀與財務報表不在服務範圍內。

從哪一份 Excel 開始

去財務部、業務部問：「每個月花你們最多時間整理的那份 Excel，是哪一份？」找到後再問：「這份表拿到之後要做什麼？」 使用者要的常是一張樞紐好的寬表，實際需要的常是下一步，例如一份差異清單。資料平台可以直接產出那一步。

給 IT 的技術說明

架構與技術選型

  • 抽取與載入：Meltano 把 ERP、營運資料庫與上傳的 Excel 載入資料倉儲（ClickHouse）。
  • 寬表轉長表：每年或每月一欄的寬表先 UNPIVOT 成每格一列才能 JOIN；版本比對是兩張長表 FULL OUTER JOIN 後算差額。
  • 資料轉換：dbt 把 Excel 的計算步驟改寫成一層層 SQL view，即書中的「函數式資料轉換」，每層中間結果都可查詢。
  • 運算放在資料端：用 SQL 在資料倉儲內計算，不把資料搬進應用程式。上述 FIFO 用 window function 實作。
  • 排程與呈現：Kestra 排程每期重跑，Metabase 產出報表。
